# Infrastructure as Code (IaC)

**Co tvoří moderní infrastrukturu**
- přechod od monolitických aplikací k distribuovaným cloudovým řešením
- složení z mnoha komponent (mikroslužeb) běžících na velkém množství serverových uzlů
- chápání infrastruktury jako entity, která se neustále vyvíjí (není statická)
- požadavek na zacházení s infrastrukturou jako se softwarovým artefaktem (verzování, testování, dokumentace)

## Evoluce správy infrastruktury

- manuální správa (fyzické zásahy, ruční konfigurace, vysoká chybovost)
- skriptování (použití shell skriptů pro částečnou automatizaci, obtížná udržovatelnost)
- nástroje pro správu konfigurací (např. Ansible, Puppet)
- plnohodnotné IaC (deklarativní definice celých prostředí včetně sítí a úložišť)

## Hlavní přínosy IaC přístupu

**Efektivita a rychlost**
- rychlé nasazení (provisioning) nových prostředí během minut místo dnů
- snadná škálovatelnost (možnost identicky replikovat infrastrukturu)
	- horizontální – přidání více instancí
	- vertikální – přidání zdrojů (CPU, memory, bandwidth)
- automatizace životního cyklu od vývoje po produkci

**Bezpečnost a stabilita**
- eliminace lidských chyb při manuálním nastavování
- konzistence prostředí (dev, test, stage a produkce jsou identické)
- **auditovatelnost** – každá změna v infrastruktuře je dohledatelná v systému správy verzí
- **rollback** – možnost snadného vrácení stavu infrastruktury

## Metody a principy IaC

**Deklarativní vs. Imperativní přístup**
- deklarativní přístup (definujeme cílový stav „co“, nástroj se postará o cestu k němu – typické pro Terraform)
- imperativní přístup (definujeme postup „jak“, tedy přesné kroky a příkazy – typické pro skriptování)

**Idempotentnost** – schopnost nástroje provést operaci opakovaně se stejným výsledkem

**Dry-run** – změny infrastruktury se pouze vypíšou

## Přehled IaC nástrojů

**Nástroje pro provisioning (vytváření zdrojů)**
- **Terraform** – nejpoužívanější platformově nezávislý nástroj pro definici infrastruktury
- Cloud-native nástroje (AWS CloudFormation, Azure Resource Manager, Google Cloud Deployment Manager)

**Nástroje pro konfiguraci (nastavení OS a aplikací)**
- **Ansible** – agentless nástroj využívající YAML a SSH pro konfiguraci uzlů
- **Chef / Puppet** – nástroje využívající agenty běžící na cílových strojích

## Související koncepty v CI/CD

**Propojení s pipeline**
- automatické spouštění IaC skriptů v rámci CI/CD pipeline
- dynamické vytváření testovacích prostředí (ephemeral environments), která jsou po testech smazána
- správa tajných klíčů a přístupových údajů (secrets management) pro infrastrukturu
