# Software Monitoring

**Základní filozofie**
- nemůžete zlepšit to, co nedokážete změřit (motto Lorda Kelvina)
- monitoring, trasování a audit událostí jako nezbytná součást provozu
- sledování pozorovatelnosti (observability) softwaru
- využití strategií pro sběr metrik pro následné vyhodnocování

## Protokolování (Logging)

**Struktura a úrovně logů**
- obsahuje časové razítko, úroveň (level), zdrojovou komponentu a samotnou zprávu
- standardní pořadí úrovní: ALL ↣ DEBUG ↣ INFO ↣ WARN ↣ ERROR ↣ FATAL ↣ OFF
- DEBUG slouží pro pomoc vývojářům při ladění aplikace
- INFO poskytuje informace o postupu aplikace a jejích stavech
- WARN upozorňuje na neočekávané události
- ERROR informuje o chybových událostech
- FATAL indikuje kritické chyby vedoucí k ukončení aplikace

## Trasování (Tracing)

**Analýza distribuovaných systémů**
- moderní cloudové aplikace jsou komplexní distribuované systémy
- trasování je nezbytné, protože ladění takto složitých celků je velmi náročné
- pomáhá sledovat cestu požadavku napříč různými mikroslužbami a komponentami

## Upozorňování (Alerting)

**Správa incidentů**
- snaha vyhnout se "přealertování" (příliš velkému množství upozornění)
- příprava scénářů pro řešení katastrof a krizových stavů
- role MOD (Master of Disaster) pro koordinaci zapojených lidí
- neposílání alertů během plánovaných odstávek a údržbových oken
- využití stavových stránek (status page) pro komunikaci s uživateli

**Spouštění alertů a indikátory**
- sledování indikátorů zdraví systému (health checks)
- jednoduché binární indikátory (služba běží/neběží) pomocí ping/echo
- skalární metriky jako vytížení CPU nebo zaplnění disku
- sledování absolutních hodnot i procentuálních podílů
- detekce anomálií a odchylek od "normálního" chování

## Statistické vyhodnocování

**Detekce odlehlých hodnot (Outliers)**
- využití statistik a strojového učení pro rozpoznání anomálií
- aplikace Gaussova normálního rozdělení
- využití percentilů (např. 90. percentil) je pro monitoring vhodnější než prostý průměr

## Sběr metrik a vizualizace

**Metody sběru (Push vs. Pull)**
- **Push přístup**
	- loggery samy posílají zprávy procesům sběratele (např. ELK stack)
	- výhody: lepší škálovatelnost, využití front zpráv
- **Pull přístup**
	- agenti aktivně stahují metriky z monitorovacích rozhraní (API) aplikací (např. Zabbix)
	- výhody: automatická detekce selhání senzoru díky pravidelnému dotazování

**Vizualizace dat**
- běžným přístupem je tvorba nástěnek (dashboardů)
- vyžadována snadná integrace s úložišti logů a tras
- podpora dotazovacích jazyků pro analýzu dat
- důraz na jednoduchost a srozumitelnost zobrazených informací

## Kategorie monitoringu

**Whitebox monitoring**
- sleduje vnitřnosti aplikace skrze monitorovací API (latence, provoz, chyby, saturace)

**Blackbox monitoring**
- sleduje externí projevy zvenčí
	- servery (CPU, RAM, I/O)
	- síťové komponenty (brány, load balancery)
