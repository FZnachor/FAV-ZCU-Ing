# Webserver a HTTP

Webové servery hrají klíčovou roli v komunikaci mezi klientem a serverem.
- Klient **generuje požadavky a přijímá odpovědi**.
- Server **přijímá požadavky a generuje odpovědi**.

Důležité je, aby tyto dva systémy byly schopny se navzájem pochopit prostřednictvím **komunikačního protokolu**.

### Komunikační protokoly

- Různé aplikace používají různé protokoly.
- Webové servery: **HTTP(s)**
- MySQL: **binární protokol přes TCP/IP**
- Webové aplikace: **REST**, **SOAP**, **AMQP**, ...

### Hypertext Transfer Protocol (HTTP)

- Textový protokol
- Pro přenos hypertextových a mediálních souborů
	- např. **HTML souborů**

1. Klient odešle požadavek (cílové URL, hlavičky, tělo).
2. Server zpracovává požadavek a odpovídá odpovědí (stavu výsledku, hlavičkám, tělu).

#### Vlastnosti HTTP

- Textový formát: jednoduché na implementaci.
- **Bezestavový**: každá žádost je nezávislá na předchozích.
- **HTTP/1.1** – jedno připojení TCP = požadavek-odpověď.
- Standardizované verze jako **HTTP/1.1** (RFC 2616) a **HTTP/2** (RFC 7540).

#### Verze HTTP

- **HTTP/1.1**: nejběžnější verze.
- **HTTP/2**: snaží se vyřešit problémy s výkonem povolením více požadavků na stejném TCP připojení.
- **HTTP/3**: nová verze pracující přes **UDP** (Google QUIC), která řeší problémy s _multiplexingem_ u HTTP/2.

### HTTP Požadavek a odpověď

HTTP požadavek má strukturu:

```
<method> <URI> <version>
<header1>
...
<headerN>
<body>
```


Například:

```http
GET /index.html HTTP/1.1
Host: www.kiv.zcu.cz
```

Metody
- **GET, OPTIONS, HEAD, TRACE** (nemění stav)
- **POST, PUT, DELETE** (mění stav)

Hlavičky
- **Host** – hostname volaného serveru
- **Origin** – jméno serveru, ze kterého přichází požadavek
- **Content-Type, Accept, Authorization**

#### HTTP Odpověď

Odpověď má strukturu:

```
<version> <code> <description>
<header1>
...
<headerN>
<body>
```

Příklad:

```http
HTTP/1.1 200 OK
Content-Type: text/plain
Content-Length: 14
...
Hello, world!
```

Stavové kódy
- **200 OK**, **204 No Content**
- **401 Unauthorized**, **403 Forbidden**, **404 Not Found**
- **500 Internal Server Error**

Hlavičky
- Location, Content-Type, Content-Length

### Cookies

- Způsob, jak ukládat data na straně klienta
- Když jsou nastaveny, prohlížeč je automaticky přidává k požadavkům
- Typické použití jako **identifikátor relace** ve stavu aplikace
	- Server přijímá ID relace prostřednictvím cookie a používá ho k vyhledávání dat relace

Cookies se nastavují prostřednictvím HTTP hlaviček:

```
Set-Cookie: name=value [; EXPIRES=dateValue] [; DOMAIN=domainName][; PATH=pathName][; SECURE][; ...]
```

#### Další atributy Cookies

- **Domain**: určuje, pro které domény je cookie platná.
- **Path**: URI podprostor, pro který je cookie platná.
- **Secure**: cookie je posílána pouze přes zabezpečený kanál (HTTPS).
- **HttpOnly**: zakazuje přístup k cookie a jejímu obsahu skrze JavaScript, což pomáhá chránit proti XSS útokům.
- **SameSite**: řídí použití cookies při _**cross-origin**_ požadavcích.

### HTML WebStorage API

- Alternativa ke cookies, kterou aplikace používají k ukládání dat v prohlížeči.
- Data nemusí být posílána serveru s každým požadavkem, ale jsou přístupná přes JavaScript API – ovlivňuje bezpečnost.
- **Session Storage** – ukládá data do zavření panelu/prohlížeče.
- **Local Storage** – ukládá data do té doby, než jsou odstraněna.

### Proxy

- Proces, kdy požadavek mezi klientem a serverem prochází mezičlánky.
- **Forward Proxy** – přesměrování požadavků klienta na externí síť.
	- klient → proxy → internet
	- používány pro centrální přístup na internet z interních sítí
	- kontrola přenášených dat, skrytí IP adresy klienta
- **Reverse Proxy** – přesměrování požadavků z externí sítě na interní servery.
	- klient → internet → proxy → content server
	- používány pro centrální přístup z internetu do interních sítí

### Protokoly Proxy

**TCP**, **UDP** – proxy na transportní vrstvě OSI modelu
- Proxy může také fungovat s jinými než HTTP protokoly.
- Nezná obsah přenášených dat (např. HTTP hlavičky).
- Nemůže modifikovat obsah bez terminace SSL.

**HTTP Reverse Proxy** (s SSL terminací)
- Může směrovat požadavky podle jejich obsahu (hlavičky, cesta).
- Umožňuje modifikaci obsahu požadavků před odesláním na backend server.
- Používána pro SSL terminaci, cache, kompresi, sprápvu přístupu, load-balancing, HA.

Proxy nahrazuje IP klienta svojí IP.
- Nechtěné pro logování, obsah dle lokace a debugging.
- Možné odeslat informace o klientovi přes HTTP hlavičky.
	- Forwarded – standardizováno
	- X-Forwarded-For, X-Forwarded-Host, X-Forwarded-Proto
